# 용의 귀환 · 게임 서버

## 1. 자리 비움 사냥 서버 (`idle.js`)

AI를 켠 채 게임을 끄면 캐릭터가 이 서버에서 계속 사냥합니다.

- 게임이 닫힐 때 캐릭터 정보(레벨·공격력·방어력·체력·물약·사냥터 몬스터)를 서버로 보냅니다.
- 서버는 1초마다 게임과 같은 공식으로 싸웁니다: 몬스터 체력·공격력·경험치·골드, 방어력 감소,
  물약(체력 45% 아래에서 40% 회복), 쓰러지면 90초 뒤 다시 출발, 레벨 업.
- 사냥하는 동안 게임과 같은 MQTT 브로커에 위치·공격을 보내서, 다른 플레이어 눈에
  「이름·AI」 캐릭터가 사냥터에서 싸우는 모습으로 보입니다.
- 다시 접속하면 그동안 얻은 경험치·골드·잡템을 받고, 쓴 물약이 빠집니다 (최대 24시간).

```
cd server
npm install
PORT=8090 node idle.js
```

| 환경 변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` | 8090 | HTTP 포트 |
| `BROKER` | `wss://broker.emqx.io:8084/mqtt` | 게임이 쓰는 브로커 (보이는 캐릭터용, `off` 로 끔) |
| `DATA` | `./data/idle.json` | 진행 상황 저장 파일 (서버를 다시 켜도 이어서 사냥) |
| `MAX_HOURS` | 24 | 한 번에 사냥하는 최대 시간 |
| `MAX_SESSIONS` | 500 | 동시에 사냥하는 최대 캐릭터 수 |
| `IDLE_KEY` | (없음) | 아래 `broker.js` 를 직접 띄울 때만, 두 서버에 같은 값(16자 이상) |

게임 페이지는 HTTPS 라서 이 서버도 **HTTPS 주소**가 있어야 합니다 (호스팅 서비스가 붙여 주는 주소면 됩니다).
게임에 서버 주소를 알려 주는 방법: `index.html` 의 `IDLE_DEFAULT` 에 주소를 넣거나, 게임 주소 뒤에
`?idle=https://서버주소` 를 한 번 붙여 접속합니다 (그 기기에 기억됨).

Docker: `docker build -t rotd-idle . && docker run -p 8090:8090 -v rotd:/data rotd-idle`

API: `POST /idle/start` (게임이 닫힐 때 sendBeacon), `POST /idle/stop` (결과 받고 종료), `GET /idle/peek?name=&token=` (진행 상황), `GET /health`.
캐릭터마다 게임이 만든 비밀값으로 보호합니다. 사냥 중인 캐릭터는 같은 비밀값으로만 결과를 받거나 바꿀 수 있습니다.

## 2. 직접 띄우는 MQTT 브로커 (`broker.js`, 선택)

게임은 기본으로 공개 MQTT 브로커(`broker.emqx.io`, 실패 시 `broker.hivemq.com`)를 씁니다.
공개 브로커는 무료지만 보장이 없으므로, 안정적으로 운영하려면 이 브로커를 직접 띄우고
게임 주소 뒤에 `?broker=wss://내서버주소` 를 붙여 접속하면 됩니다.

```
PORT=8080 IDLE_KEY=<16자 이상 비밀값> node broker.js
```

- 서버마다 최대 200명. 게임 토픽 외의 발행과 2KB 넘는 메시지는 막고, 클라이언트마다 초당 메시지 수를 제한합니다.
- `idle.js` 는 `IDLE_KEY` 를 비밀번호로 접속하며 인원·메시지 제한을 받지 않습니다.
- HTTPS 게임 페이지에서 접속하려면 `wss://`(TLS)가 필요합니다. 호스팅 서비스의 HTTPS 프록시 뒤에 두세요.
